|---|---|---|
| Вывод сообщений на экран | `print(...)` | `UI.show_message(message)` |
| Запрос строки у пользователя | `input(...)` | `UI.get_input(prompt)` |

| Управление циклом игры | `while attempts < max_attempts:` | `Game.run()` |
# 1.2
## 1 Какие классы вы выделите? Обоснуйте.
* `UI`: Отвечает исключительно за консольный ввод/вывод. Изолирует работу с терминалом (`input`/`print`).
* `Player`: Хранит состояние участника (имя, количество совершённых попыток) и отвечает за формирование хода.
* `Game`: Ведущий/оркестратор. Хранит правила (секретное число, лимит попыток), сравнивает догадки игрока с секретом и управляет игровым циклом.

## 2 Какие атрибуты будут приватными (`_name`)? Почему?
 В `Game`: `_secret`, `_max_attempts`, `_ui`
 В `Player`: `_name`, `_attempts`, `_ui`

Причина: Инкапсуляция и защита целостности данных. Внешний код не должен напрямую подменять секретное число посреди партии или скручивать счётчик попыток.

## 3. Какие методы будут публичными? Почему?
 `Game.run()` 
 `Game.check_guess(guess)` 
 `Player.make_guess()` 
 `Player.increment_attempts()` 
 `UI.show_message()`, `UI.get_input()` 

 Причина: Все они вызываются другими функциями и являются API

## 4. Есть ли в исходном коде God Object? Как вы это поняли?
Не совсем была God Function которая выполняла роль God Object, а конкретно `play_guess_number_procedural`. В ней была вся логика, ввод/вывод, храненией всех данных и т.п.
